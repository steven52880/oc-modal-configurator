# OpenCode 配置编辑器 —— 需求与功能规格说明书

## 1. 背景与目标

OpenCode 的核心配置文件 `opencode.json` 承载了多个 AI 服务提供商（Provider）及其下属模型（Model）的连接参数、Token 限制、多模态输入输出能力、推理强度变体（Variants）、计费价格及自定义请求头。随着接入模型数量增加（尤其是使用 NewAPI、OneAPI、OpenRouter 等聚合/中转服务时），手写维护几百行甚至上千行的 JSON 存在以下痛点：

1. **字段繁杂且易出错**：同一个提供商下往往包含数十个模型，手动补齐每个模型的 `limit.context`、`limit.output`、`modalities` 和 `variants` 极易出现拼写或类型错误。
2. **批量修改成本高**：当需要为同一批模型统一开启某项能力、统一修改上下文长度或复制模态配置时，文本编辑器缺乏二维表格级别的批量操作能力。
3. **默认参数查阅困难**：用户难以记住每个模型的官方最大上下文、输出长度及支持的推理档位，需要对照 `models.dev` 逐一查询。
4. **手写与工具混用易丢字段**：部分可视化工具只保存自己认识的表单字段，导致用户在 `opencode.json` 中配置的 `plugin`、`$schema` 或未知新属性被覆盖丢失。

**项目目标**：构建一款**轻量、原生窗口、高信息密度、100% 无损保存**的桌面配置编辑器，让管理几十个提供商与数百个模型像操作电子表格一样直观高效。

---

## 2. 核心设计原则

1. **纯粹桌面体验，零内核冗余**：调用操作系统内置 WebView，不打开外部浏览器，也不打包百兆 Chromium。
2. **四层渐进式披露（4-Layer Hierarchy）**：按配置项的使用频率严格分层，主界面只展示最高频列，进阶参数收折并带状态角标，生僻元数据只读展示或底层无损透传。
3. **电子表格级批量效率**：结合「双击单元格就地编辑」、「二维框选 + 列锁定批量粘贴」、「框选一键设为默认值」与「`<...>` 混合状态批量弹窗编辑」。
4. **工具状态与目标配置严格分离**：工具自身的窗口、分栏与缓存数据绝不混入用户的 `opencode.json`。
5. **离线与内网完备兜底**：任何网络请求（拉取 `/models` 或更新 `models.dev`）失败时，均提供清晰的本地兜底路径与热重载机制。

## 3. 配置项四层分级规格

### 3.1 层级 1：主界面上下分栏双表格（高频速览与就地操作）

主窗口采用上下可拖拽分栏布局（默认上栏占 `40%`，下栏占 `60%`，范围限制在 `20%–80%` 并自动持久化）。

#### 上栏：提供商表格 (`ProviderTable`)

| 列序 | 列标识 (`id`) | 展示内容与格式 | 交互行为 |
| :--- | :--- | :--- | :--- |
| 行首勾选 | - | 复选框 (`Checkbox`) | 勾选/取消勾选提供商行（框选单元格时自动勾选对应行） |
| 行号手柄 | - | 行序号 + 详情触发区 | **单击**直接打开该提供商的「详细编辑弹窗」 |
| 1 | `name` | 提供商显示名称 | 单击/拖拽框选；**双击**切换为紧凑文本框就地编辑 |
| 2 | `key` | 提供商唯一标识符（等宽字体） | 单击/拖拽框选；**双击**就地编辑（重命名自动校验唯一性） |
| 3 | `npm` | AI SDK 驱动包名（等宽字体） | 单击/拖拽框选；**双击**切换为 `Autocomplete (freeSolo)`，内置常用预设并支持自由输入 |
| 4 | `baseURL` | `options.baseURL`（单行省略号截断 + 悬浮完整 Tooltip） | 单击/拖拽框选；**双击**切换为文本框就地编辑 |
| 行尾操作 | - | 「编辑」「删除」图标按钮 | 单击打开详情弹窗或删除当前提供商 |

#### 下栏：模型表格 (`ModelTable`)

- **视图分组排序**：默认按模型标识符的第一段名称（如 `gpt`、`deepseek`、`claude`、`gemini`、`kimi`）在视图层归类并按字母排序，模型标识符左侧展示紧凑的前缀胶囊标签。**注意**：视图排序不改变底层 `provider.models` 的存储顺序（除非新增、重命名或删除）。

| 列序 | 列标识 (`id`) | 展示内容与格式 | 交互行为 |
| :--- | :--- | :--- | :--- |
| 行首勾选 | - | 复选框 (`Checkbox`) | 勾选/取消勾选模型行（切换上方提供商时自动清空） |
| 行号手柄 | - | 行序号 + 详情触发区 | **单击**直接打开该模型的「详细编辑弹窗」 |
| 1 | `key` | 模型标识符（前缀色标 + 等宽字体） | 单击/拖拽框选；**双击**就地重命名（校验当前提供商内唯一性） |
| 2 | `context` | `limit.context`（右对齐等宽数字 `tabular-nums`） | 单击/拖拽框选；**双击**切换为数字输入框就地编辑 |
| 3 | `output` | `limit.output`（右对齐等宽数字 `tabular-nums`） | 单击/拖拽框选；**双击**切换为数字输入框就地编辑 |
| 4 | `inputModalities` | `modalities.input`（5 个紧凑图标按钮：`text`/`image`/`audio`/`video`/`pdf`） | **直接点击图标**切换启停（未启用为灰色，启用为各模态专属彩色，悬浮显示中英文提示）；支持框选复制粘贴与框选设为默认 |
| 5 | `outputModalities` | `modalities.output`（5 个紧凑图标按钮） | 同上 |
| 6 | `variants` | `variants`（7 个紧凑复选框，大写标签：`NONE`/`MIN`/`LOW`/`MED`/`HIGH`/`XHIGH`/`MAX`） | **直接点击勾选**自动维护底层 `variants.<key>` 对象（保留已有自定义属性）；悬浮显示完整变体名与中文说明 |
| 行尾操作 | - | 「编辑」「删除」图标按钮 | 单击打开详情弹窗或删除当前模型 |

### 3.2 层级 2：详情与批量编辑弹窗 —— 默认展开核心区

单击行号、点击行尾编辑图标，或勾选多行后点击工具栏「编辑」按钮时打开。

#### 提供商弹窗核心区（6 项）

1. **提供商标识符 (`key`)**：单条编辑时可修改并校验唯一性；批量编辑时只读，显示 `已选 N 个提供商`。
2. **提供商名称 (`name`)**：文本输入框（批量不一致时显示 `placeholder="<...>"`）。
3. **提供商类型 (`npm`)**：`Autocomplete (freeSolo)`，提供 `@ai-sdk/openai`、`@ai-sdk/openai-compatible`、`@ai-sdk/anthropic`、`@ai-sdk/google` 下拉项，并固定提示：`/v1/responses 推荐 @ai-sdk/openai；/v1/chat/completions 推荐 @ai-sdk/openai-compatible`。
4. **API 基础地址 (`options.baseURL`)**：等宽字体输入框。
5. **API 密钥 (`options.apiKey`)**：
   - 支持密码掩码显隐切换（眼睛图标）；
   - 实时调用后端 `describe_api_key` 显示状态徽章（字面量密钥 / 环境变量 `{env:...}` 是否已设置 / 密钥文件 `{file:...}` 是否存在），**绝不在前端明文回显解析后的密钥内容**；
   - 提供快捷插入菜单，一键填入 `{env:VAR_NAME}` 或 `{file:~/.secrets/key}` 模板。
6. **启用缓存键 (`options.setCacheKey`)**：支持三态选择（`未设置 null` / `启用 true` / `禁用 false`；批量不一致时支持维持 `<...>` 原值）。

#### 模型弹窗核心区（6 组，带 `models.dev` 默认值胶囊）

当模型在本地 `models.dev` 缓存中匹配到默认配置时，对应字段右侧会展示可点击的 `默认: xxx` 胶囊（`Chip`），点击即可一键填入输入框或复选框：

1. **模型标识符 (`key`) 与显示名称 (`name`)**：双列并排；批量模式下标识符只读。
2. **Token 限制 (`limit.context` / `limit.output`)**：双列数字框，附带 `128K`、`200K`、`1M` 快捷填入按钮及默认值胶囊。
3. **输入支持的模态 (`modalities.input`)**：5 个带文字说明的彩色/灰色图标切换器（批量模式下支持 `<...>` 混合状态展示与一键重置）。
4. **输出支持的模态 (`modalities.output`)**：同上。
5. **变体档位 (`variants`)**：水平排列 `NONE`、`MIN`、`LOW`、`MED`、`HIGH`、`XHIGH`、`MAX` 复选框（批量模式下部分行勾选时显示 `indeterminate` 半选状态），旁侧附带「默认变体」胶囊。
6. **核心能力开关（4 项网格）**：
   - `支持附件 (attachment)`、`工具调用 (tool_call)`、`推理模型 (reasoning)`、`温度调节 (temperature)`；
   - 每项均支持 `未设置 (null)` / `开启 (true)` / `关闭 (false)`（批量不一致时额外提供 `保持原样 (<...>)`），并带默认值胶囊。

---

### 3.3 层级 3：详情与批量编辑弹窗 —— 默认折叠进阶区 (`Accordion`)

默认收起以保持弹窗清爽。**当某个折叠面板内已有非空配置项时，面板标题右侧自动显示醒目的 `已配置 N 项` 角标**。

#### 提供商折叠面板（2 个）

1. **超时策略 (`timeout` / `headerTimeout` / `chunkTimeout`)**：
   - 每项支持三种模式：`未设置 (null)`、`禁用超时 (false)`、或输入非负毫秒整数（`ms`）。
2. **自定义请求头 (`options.headers`) 与扩展参数 (`optionsExtra`)**：
   - `options.headers`：动态键值对列表编辑器（支持增删行，批量模式下支持保留 `<...>` 混合状态或统一覆盖）；
   - `optionsExtra`：多行 JSON 代码框（带实时语法校验，用于编辑除标准字段外的其它 `options` 属性）。

#### 模型折叠面板（3 个）

1. **推理参数与思考配置 (`options` & `interleaved`)**：
   - `默认推理强度 (options.reasoningEffort)`：`未设置 / none / minimal / low / medium / high / xhigh / max`；
   - `输出详略度 (options.textVerbosity)`：`未设置 / low / medium / high`；
   - `流式交错思考字段 (interleaved)`：`未设置 / false / true / reasoning_content / reasoning / reasoning_text`（底层自动在布尔值与 `{"field": "..."}` 对象间转换）；
   - `思考预算 (options.thinking.budgetTokens)`：数字输入框。
2. **最大输入限制与计费价格 (`limit.input` & `cost`)**：
   - `最大输入限制 (limit.input)`：数字输入框 + 默认值胶囊；
   - `计费价格 (cost.input / output / cache_read / cache_write)`：双列宽松网格布局，带 `$/1M` 单位前缀与官方默认价格一键填入胶囊。
3. **单模型驱动覆盖、请求头 (`headers`) 与高级 JSON**：
   - `单模型驱动包覆盖 (provider.npm)`：允许在同一提供商下为个别模型单独指定 `@ai-sdk/openai` 或 `@ai-sdk/openai-compatible`；
   - `单模型端点覆盖 (provider.api)` 与 `底层映射 ID (id)`；
   - `模型专属请求头 (headers)`：键值对列表编辑器；
   - `自定义 options / 变体高级参数 JSON`：允许直接编辑 `variants` 内部对象属性及未知 `options` 字段。

---

### 3.4 层级 4：只读元数据与底层无损透传

- **只读副标题徽章**：若模型存在 `family`、`release_date`、`last_updated`、`knowledge`、`open_weights`、`canonical_model_id`、`status` 等元数据，在模型编辑弹窗顶部标题下方以只读信息条展示，不占用表单空间。
- **100% 无损保存保证**：
  - 顶层非 `provider` 字段（如 `plugin`、`$schema`、`model`、`agent`、`mcp` 等）保存在 `document.preserved` 中，写回时原样输出；
  - 提供商与模型各层级中的未知字段（`provider.extra`、`provider.optionsExtra`、`model.extra`、`limit.extra`、`cost.extra`、`model.provider.extra`）以及未知模态字符串，在编辑与保存全流程中**绝不丢失**。

## 4. 核心交互与业务规则

### 4.1 类 Excel 单元格框选与列锁定复制粘贴

1. **二维自由框选**：在提供商表或模型表的任意数据单元格上按下鼠标左键并拖拽，可框选矩形区域。
2. **自动勾选对应行**：当存在活动的框选矩形时，系统自动将该矩形覆盖的所有行在左侧复选框中勾选（方便紧接着点击「编辑」或「删除」）；当框选消失时，已勾选的行保持勾选状态。
3. **失焦自动清除框选**：当鼠标点击表格容器（含该表工具栏）以外的区域时，自动清空当前表格的单元格框选高亮（不清除复制模式锁定）。
4. **单行连续复制与列锁定**：
   - 框选**同一行**内的 1 个或多个连续单元格，按 `Ctrl+C`：
     - 记录所选列区间 `[colStart..colEnd]` 及其序列化后的值；
     - 工具栏显示紧凑的 **「复制模式」** 标记，目标列背景微亮提示；
   - 若框选了多行按 `Ctrl+C`，底部弹出 Toast 提示：「仅支持复制单行连续单元格，请在同一行内框选后按 Ctrl+C」。
5. **跨行批量粘贴**：
   - 处于「复制模式」时，再次在表内拖拽框选，横向列范围自动锁定在已复制的列上，纵向可跨越任意多行；
   - 按 `Ctrl+V`，将复制的单行数据批量写入所选全部行的对应列。
6. **退出与清选 (`Esc`)**：
   - 若当前处于「复制模式」，按 `Esc` 优先退出「复制模式」；
   - 若未处于「复制模式」，按 `Esc` 清空当前表格已勾选的行。

### 4.2 框选一键「默认」

- 在模型表格中框选任意单元格区域（例如框选 10 个模型的 `context`、`output` 和 `inputModalities` 列），点击模型工具栏的 **「默认」** 按钮：
  - 批量调用后端 `match_models_defaults`；
  - **仅将框选区域所涉及的列**重置为各自模型在 `models.dev` 中的默认值，未框选的列保持不变。

### 4.3 分组拉取与添加模型弹窗 (`AddModelsDialog`)

点击模型工具栏「添加」按钮打开弹窗，提供两种模式标签页：

1. **从提供商接口拉取 (`/models`)**：
   - 根据当前提供商的 `options.baseURL` 和解析后的 `options.apiKey` 实时请求 `${baseURL}/models`；
   - 自动为每个远端模型匹配本地模型库中的默认参数；
   - 若提供商未配置 `baseURL`、密钥未就绪或网络不可达，展示明确错误原因并提供一键切换到「从本地模型库检索」的按钮。
2. **从本地模型库检索 (`models.dev`)**：
   - 支持按模型库提供商下拉筛选或输入关键词实时搜索（也支持「加载全部」）；
3. **前缀折叠分组与智能带入**：
   - 所有候选模型按第一段名称（如 `deepseek`、`gpt`、`claude`）归类为可折叠面板；
   - 支持勾选分组头部复选框**整组全选/取消**，或展开后勾选单个模型；
   - 已存在于当前提供商下的模型自动标记为「已存在」并置灰跳过；
   - 点击「确认添加」后，自动将所选模型及其匹配到的默认 `limit`、`modalities`、`variants`、`capabilities`、`cost`、`meta` 一并写入当前提供商。

### 4.4 手动保存、备份与冲突恢复

- 所有表格就地编辑、复选框点击、粘贴、增删行、弹窗确认均只更新前端内存状态，顶部栏显示醒目的 **「未保存」** 标记。
- 点击顶部 **「保存」** 按钮或按快捷键 `Ctrl+S` 时才写入磁盘：
  - 若目标文件已存在，先复制生成同目录 `<filename>.bak` 备份；
  - 采用临时文件 `.tmp` 原子替换写入；
  - 若文件在外部被其它程序修改（`mtimeNs` 不一致），立即拦截并弹出「配置文件已被外部修改」对话框，由用户选择「重新加载外部文件」或「强制覆盖保存」。
